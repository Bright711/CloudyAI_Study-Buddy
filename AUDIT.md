# CloudyAI Study Buddy: initial audit

## Scope and evidence

This audit inspected the checked-in documentation, root and backend manifests, Next.js pages/API routes, Supabase clients and schema, misconception engine, seed importer, original static frontend, and repository Git state. Work is isolated on `audit/production-readiness`. The static prototype was removed after the API-connected React dashboard and quiz flow were added; backend limitations are documented below.

The tracked `api/.env.local` was identified by Git metadata only. Its contents were intentionally not read or logged. No live database, deployment, secret store, or third-party service was accessed. The local Supabase schemas and remote migration history therefore remain unverified.

## Dependency map

```text
Active Next.js React UI
  ├─ / → account status + approved question count
  ├─ /practice → question API → authenticated session + answer submission
  └─ /auth → Supabase browser auth
       └─ same-origin API routes → Supabase database

Misconception engine → privileged server client (not wired into submit flow)
Tutor prompt → disconnected prompt file (no AI provider or route)
Supabase schema.sql → initial DDL; no checked-in migration chain
```

The inventory is based on source inspection; no endpoint was exercised against an external database.

## Database reconciliation status

- Database technology: Supabase PostgreSQL, based on `schema.sql` and client dependencies.
- Local schema: `backend/supabase/schema.sql` defines five tables and supporting indexes, enables RLS, and defines no policies, functions, triggers, or migration tracking.
- Migration history: no versioned migration files were found.
- Expected relationships: options belong to questions; attempts belong to sessions/questions/options; evidence belongs to attempts. Session ownership uses `auth.users`.
- Duplicate question-bank JSON exists in `backend/` and `data/`; source of truth is unresolved.
- Development/staging/production schemas and existing records: not inspected. No migration was applied.

Do not convert the current schema file directly into a production migration or mark any migration applied until an authorized read-only comparison establishes the target state and recovery plan.

## Baseline checks

- `npm ci --prefix backend`: passed from the checked-in lockfile; installed 368 packages and reported 0 vulnerabilities. npm warned that ESLint 9 is deprecated and that `unrs-resolver`'s install script was not approved by npm's script policy.
- `npm audit --prefix backend --omit=dev`: passed; 0 production dependency vulnerabilities reported.
- `npm --prefix backend run lint`: passed with no warnings after removing the unused import and correcting internal navigation.
- `Set-Location backend; npx tsc --noEmit`: passed after replacing the generated `LayoutProps` dependency.
- `npm --prefix backend run build`: passed with placeholder Supabase values only. A prior run logged a `cookies()` prerender rejection from `/api/auth/me`; adding `unstable_rethrow` fixed it, and the final build completed without that warning.
- `git diff --check` and `git diff --cached --check`: passed.
- Browser inspection: dashboard, sign-in page, and practice route rendered locally. At a 390px viewport, body width was 375px (no horizontal overflow); mobile menu visibility was observed. API requests returned expected unauthenticated `401` and question-service `500` responses with placeholder credentials, so only the guest/blocked states were inspectable.
- Authenticated API, database, RLS, quiz mutation, secret-history scanner, and real-data UI checks: not run. No automated test suite or CI workflow exists.
